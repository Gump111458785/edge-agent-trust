## 设计

在部署信任配置中增加可选 `checkpoint`，声明 `provider: fabric`、B 的连接配置路径和最大读取耗时。配置存在后，每次 `ReleaseSnapshot.load` 都在本地验签后核对独立状态；不缓存跨请求的肯定结果，不降级为仅本地校验。`ROLE_C_REQUIRE_CHECKPOINT=1` 要求配置存在，适用于正式消费进程；旧的纯本地实验配置保持兼容并明确其范围。

使用 B 既有 `FabricClient` / `ReadRelease`，核对完整 ReleaseRef、未撤销标志、提交回执和读取耗时。读失败或格式异常沿用 `STATE_UNAVAILABLE`，版本或撤销不符报 `CHECKPOINT_MISMATCH`。因此 A、D 原有错误映射可以沿用。RAG 对全局状态不可用返回 503，不能返回部分命中或把依赖故障伪装成正常空结果。

管理员 CLI 提供显式 `--anchor-config`，本地签名验证成功后使用独立发布身份调用 B 的发布/撤销函数。消费端的连接配置只需读权限，不持有发布签名私钥；两个存储间不声称具有原子事务。

## 检查重点

- 配置错字、缺少检查点及不合法超时不能悄悄关闭保护。
- 布尔版本、错误摘要、未知字段和格式不合法的回执不能冒充有效状态。
- 撤销、完整本地数据库回滚、同版本不同摘要、远端缺失记录都应拒绝。
- 读取超过时间上限或返回比已见区块更旧的状态应拒绝；并发不破坏已见区块上界。
- 网络错误、索引已产生部分命中以及 CLI 重试不能造成未经核验内容或权限写入。

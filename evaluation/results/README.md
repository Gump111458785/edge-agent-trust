# 访客区申领边界实验

`python -m evaluation.run_boundary` 按 5 个时长 × 4 个预约余量 × 6 个情形逐一创建独立 SQLite。前五种配置复现汇报的 600 次首次办理结果。第六种配置复用同一组 120 种情形，启用执行器的访客确认校验。

- [boundary-v2-summary.json](boundary-v2-summary.json) 是本次运行的汇总。
- `boundary-v2-runs.csv.gz` 是本次逐次结果。每条含评分、首次结果、重签结果、权限表快照、令牌消费及首次延迟。也可从运行器得到完整 JSON。
- 评分依据为用户是否要求开通、预约在执行时是否有效、时长是否在 60 分钟内，以及 SQLite 状态变化。
- 首次延迟包括本地测试客户端和验证逻辑。时间边界使用实验时钟，59/60 秒不计入墙钟时延。表中不包含云端推理、专网、用户等待或真实审批延迟。
- 两个网关配置只在已有令牌因证据变化或超时被拒后进行重签。三个起初就未签发、后来预约延长的申请不计入重签恢复分子。
- 查询场景提供结构化申请，测量给定提案下的写入结果。真实 Agent 发出此类提案的频率另行测量。

Fabric 对照可用 `python -m role_b.tests.experiment "$work" --repeat 20` 记录每组 20 个独立数据库样本、P50/P95 以及审批读取返回至事务完成的耗时上界。该重复测量入口与本地访客区延迟口径不同。
